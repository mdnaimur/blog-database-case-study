# Blog System Database Schema — Case Study Documentation

> **Project:** Blog Management Platform  
> **Database:** PostgreSQL  
> **Version:** 1.0  
> **Date:** 2026-07-25

---

## 1. Introduction

This document describes the relational database schema for a **Blog Management Platform**. The system supports three user roles (`admin`, `author`, `reader`), content publishing workflows, category-based organization, reader engagement through comments, and view analytics.

### Scope
- User authentication and role-based access
- Author profile management
- Blog post lifecycle (`draft` → `published` → `archived`)
- Category-based post taxonomy
- Comment system
- View tracking (aggregated counts + audit logs)

---

## 2. Design Decisions

| Decision | Rationale |
|----------|-----------|
| **Separate `users` and `authors` tables** | Uses a **role-extension pattern**. `users` holds authentication data; `authors` holds profile data. This keeps the base user table lean while allowing 1:1 extension for authors. |
| **Enums over lookup tables** | `role`, `author_status`, and `post_status` are enums for **type safety** and **query simplicity**. These values rarely change and do not require user-managed configuration. |
| **Denormalized `post_view_count`** | A separate counter table avoids expensive `COUNT(*)` queries on `post_view_logs`. Updated via triggers or application logic. |
| **`post_view_logs` audit table** | Stores every individual view event for **analytics** and **auditability**. Anonymous views are supported (`user_id` is nullable). |
| **Deferrable FK constraints** | Allows batch inserts/updates within a transaction before constraints are enforced, useful for data migration and complex writes. |
| **Junction table `post_categories`** | Supports **many-to-many** relationship between posts and categories. |

## 4. Schema Reference

### 4.1 Enumerated Types

#### `role`
Defines the access level of a user account.

| Value | Description |
|-------|-------------|
| `admin` | Full system access: manage users, posts, categories, and settings. |
| `author` | Can create, edit, and publish blog posts under their profile. |
| `reader` | Can read published posts and leave comments. |

#### `author_status`
Tracks the operational state of an author profile.

| Value | Description |
|-------|-------------|
| `active` | Author can publish and manage content. |
| `inactive` | Author temporarily disabled (e.g., on leave). |
| `banned` | Author permanently restricted from publishing. |

#### `post_status`
Controls the visibility and lifecycle of a blog post.

| Value | Description |
|-------|-------------|
| `draft` | Post is being written; not visible to readers. |
| `published` | Post is live and visible to all readers. |
| `archived` | Post is retained but no longer actively displayed. |

---

### 4.2 Tables

#### `users`
Base authentication and authorization table. Every person in the system has exactly one record here.

| Column | Type | Constraints | Default | Description |
|--------|------|-------------|---------|-------------|
| `user_id` | `BIGINT` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` | auto-increment | Unique identifier for the user. |
| `username` | `VARCHAR(255)` | `UNIQUE`, `NOT NULL` | — | Public display name. |
| `email` | `VARCHAR(255)` | `UNIQUE`, `NOT NULL` | — | Login credential and notification target. |
| `password` | `VARCHAR(255)` | `NOT NULL` | — | **Hashed** password (bcrypt/Argon2). Never store plaintext. |
| `role` | `role` | — | `'reader'` | System-wide access role. |
| `created_at` | `TIMESTAMP` | — | `NOW()` | Account creation timestamp. |

**Notes:**
- The `password` field must store only cryptographically hashed values.
- `role` determines whether a user can be linked to the `authors` table.

---

#### `authors`
Extended profile for users who have the `author` role. One-to-one relationship with `users`.

| Column | Type | Constraints | Default | Description |
|--------|------|-------------|---------|-------------|
| `author_id` | `BIGINT` | `PRIMARY KEY` | — | References `users.user_id` (1:1). |
| `first_name` | `VARCHAR(255)` | `NOT NULL` | — | Author's first name. |
| `last_name` | `VARCHAR(255)` | — | — | Author's last name (optional). |
| `bio` | `TEXT` | — | — | Short biography or description. |
| `profile_picture_url` | `TEXT` | — | — | URL to the author's profile image. |
| `author_status` | `author_status` | — | `'active'` | Operational status of the author. |
| `created_at` | `TIMESTAMP` | — | — | Profile creation timestamp. |
| `updated_at` | `TIMESTAMP` | — | — | Last profile update timestamp. |

**Notes:**
- Only users with `role = 'author'` or `'admin'` should have entries here.
- `author_status` is independent of `users.role`; an author can be banned without deleting their account.

---

#### `blog_posts`
Core content table storing all blog articles.

| Column | Type | Constraints | Default | Description |
|--------|------|-------------|---------|-------------|
| `blog_post_id` | `BIGINT` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` | auto-increment | Unique post identifier. |
| `author_id` | `BIGINT` | `NOT NULL` | — | References `authors.author_id`. |
| `title` | `VARCHAR(255)` | `NOT NULL` | — | Post headline. |
| `content` | `TEXT` | `NOT NULL` | — | Full post body (Markdown/HTML). |
| `post_status` | `post_status` | — | `'draft'` | Current lifecycle state. |
| `created_at` | `TIMESTAMP` | — | `CURRENT_TIMESTAMP` | When the post was first created. |
| `published_at` | `TIMESTAMP` | — | `NULL` | When the post was first published. |
| `updated_at` | `TIMESTAMP` | — | `CURRENT_TIMESTAMP` | Last modification timestamp. |

**Notes:**
- `published_at` should be set by application logic when `post_status` transitions to `'published'`.
- `updated_at` should be refreshed on every edit.

---

#### `categories`
Taxonomy table for organizing posts by topic.

| Column | Type | Constraints | Default | Description |
|--------|------|-------------|---------|-------------|
| `cat_id` | `BIGINT` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` | auto-increment | Unique category identifier. |
| `category_name` | `VARCHAR(255)` | `UNIQUE`, `NOT NULL` | — | Human-readable category label. |
| `description` | `TEXT` | — | — | Optional category description. |

---

#### `post_categories`
Junction table implementing the many-to-many relationship between posts and categories.

| Column | Type | Constraints | Default | Description |
|--------|------|-------------|---------|-------------|
| `blog_post_id` | `BIGINT` | `NOT NULL`, part of `PRIMARY KEY` | — | References `blog_posts.blog_post_id`. |
| `cat_id` | `BIGINT` | `NOT NULL`, part of `PRIMARY KEY` | — | References `categories.cat_id`. |

**Notes:**
- Composite primary key `(`blog_post_id`, `cat_id`)` ensures a post cannot be linked to the same category twice.
- A single post can belong to **multiple** categories.

---

#### `comments`
Reader engagement table for post discussions.

| Column | Type | Constraints | Default | Description |
|--------|------|-------------|---------|-------------|
| `comment_id` | `BIGINT` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` | auto-increment | Unique comment identifier. |
| `content` | `TEXT` | `NOT NULL` | — | Comment body. |
| `created_at` | `TIMESTAMP` | — | `CURRENT_TIMESTAMP` | When the comment was posted. |
| `blog_post_id` | `BIGINT` | `NOT NULL` | — | References `blog_posts.blog_post_id`. |
| `user_id` | `BIGINT` | `NOT NULL` | — | References `users.user_id` (the commenter). |

**Notes:**
- Currently supports **flat** comments only (no threading/replies).
- All commenters must be registered users.

---

#### `post_view_count`
Denormalized counter for fast read performance.

| Column | Type | Constraints | Default | Description |
|--------|------|-------------|---------|-------------|
| `blog_post_id` | `BIGINT` | `PRIMARY KEY` | — | References `blog_posts.blog_post_id` (1:1). |
| `view_count` | `BIGINT` | — | `0` | Total number of views. |

**Notes:**
- This table should be updated via application logic or database triggers when `post_view_logs` is inserted.
- Separating this from `blog_posts` avoids row bloat and lock contention on the main content table.

---

#### `post_view_logs`
Audit trail for every individual post view event.

| Column | Type | Constraints | Default | Description |
|--------|------|-------------|---------|-------------|
| `view_log_id` | `BIGINT` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` | auto-increment | Unique log entry identifier. |
| `blog_post_id` | `BIGINT` | `NOT NULL` | — | References `blog_posts.blog_post_id`. |
| `user_id` | `BIGINT` | — | `NULL` | References `users.user_id`. `NULL` = anonymous viewer. |
| `viewed_at` | `TIMESTAMP` | — | `CURRENT_TIMESTAMP` | Exact timestamp of the view event. |

**Notes:**
- Nullable `user_id` supports tracking views from non-logged-in visitors.
- This table can grow very large; consider **partitioning** by `viewed_at` in production.

## 5. Complete DDL (Clean & Fixed)

```sql
-- ============================================
-- BLOG SYSTEM DATABASE SCHEMA
-- Case Study: Blog Management Platform
-- Database: PostgreSQL
-- ============================================

-- --------------------------------------------
-- ENUM TYPES
-- --------------------------------------------

CREATE TYPE "role" AS ENUM (
  'admin',    -- Full system access
  'author',   -- Can create and manage posts
  'reader'    -- Can read and comment
);

CREATE TYPE "author_status" AS ENUM (
  'active',   -- Author can publish
  'inactive', -- Author temporarily disabled
  'banned'    -- Author permanently restricted
);

CREATE TYPE "post_status" AS ENUM (
  'draft',      -- Being written, not visible
  'published',  -- Live and visible to readers
  'archived'    -- No longer active but retained
);

-- --------------------------------------------
-- CORE TABLES
-- --------------------------------------------

CREATE TABLE "users" (
  "user_id"       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "username"      VARCHAR(255) UNIQUE NOT NULL,
  "email"         VARCHAR(255) UNIQUE NOT NULL,
  "password"      VARCHAR(255) NOT NULL,
  "role"          "role" DEFAULT 'reader',
  "created_at"    TIMESTAMP DEFAULT (NOW())
);

COMMENT ON TABLE "users" IS 'Base user accounts for authentication and authorization';
COMMENT ON COLUMN "users"."password" IS 'Must be bcrypt/argon2 hashed, never plaintext';

CREATE TABLE "authors" (
  "author_id"           BIGINT PRIMARY KEY,
  "first_name"          VARCHAR(255) NOT NULL,
  "last_name"           VARCHAR(255),
  "bio"                 TEXT,
  "profile_picture_url" TEXT,
  "author_status"       "author_status" DEFAULT 'active',
  "created_at"          TIMESTAMP,
  "updated_at"          TIMESTAMP
);

COMMENT ON TABLE "authors" IS 'Extended profile for users with author role';
COMMENT ON COLUMN "authors"."author_id" IS 'References users.user_id (1:1 relationship)';

CREATE TABLE "blog_posts" (
  "blog_post_id"  BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "author_id"     BIGINT NOT NULL,
  "title"         VARCHAR(255) NOT NULL,
  "content"       TEXT NOT NULL,
  "post_status"   "post_status" DEFAULT 'draft',
  "created_at"    TIMESTAMP DEFAULT (CURRENT_TIMESTAMP),
  "published_at"  TIMESTAMP,
  "updated_at"    TIMESTAMP DEFAULT (CURRENT_TIMESTAMP)
);

COMMENT ON TABLE "blog_posts" IS 'Main content table for blog articles';
COMMENT ON COLUMN "blog_posts"."published_at" IS 'Timestamp when post was first published';

CREATE TABLE "categories" (
  "cat_id"          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "category_name"   VARCHAR(255) UNIQUE NOT NULL,
  "description"     TEXT
);

COMMENT ON TABLE "categories" IS 'Taxonomy for organizing blog posts';

CREATE TABLE "post_categories" (
  "blog_post_id"  BIGINT NOT NULL,
  "cat_id"        BIGINT NOT NULL,
  PRIMARY KEY ("blog_post_id", "cat_id")
);

COMMENT ON TABLE "post_categories" IS 'Junction table for many-to-many: posts <-> categories';

CREATE TABLE "comments" (
  "comment_id"    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "content"       TEXT NOT NULL,
  "created_at"    TIMESTAMP DEFAULT (CURRENT_TIMESTAMP),
  "blog_post_id"  BIGINT NOT NULL,
  "user_id"       BIGINT NOT NULL
);

COMMENT ON TABLE "comments" IS 'Reader comments on blog posts';

CREATE TABLE "post_view_count" (
  "blog_post_id"  BIGINT PRIMARY KEY,
  "view_count"    BIGINT DEFAULT 0
);

COMMENT ON TABLE "post_view_count" IS 'Denormalized counter for fast read performance';

CREATE TABLE "post_view_logs" (
  "view_log_id"   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "blog_post_id"  BIGINT NOT NULL,
  "user_id"       BIGINT,
  "viewed_at"     TIMESTAMP DEFAULT (CURRENT_TIMESTAMP)
);

COMMENT ON TABLE "post_view_logs" IS 'Audit trail for individual post views';
COMMENT ON COLUMN "post_view_logs"."user_id" IS 'NULL when viewed by non-logged-in users';

-- --------------------------------------------
-- INDEXES
-- --------------------------------------------

CREATE INDEX "idx_blog_posts_author" ON "blog_posts" ("author_id");
CREATE INDEX "idx_blog_posts_status" ON "blog_posts" ("post_status");
CREATE INDEX "idx_post_view_logs_post" ON "post_view_logs" ("blog_post_id");
CREATE INDEX "idx_post_view_logs_user" ON "post_view_logs" ("user_id");

-- --------------------------------------------
-- FOREIGN KEY CONSTRAINTS
-- --------------------------------------------

ALTER TABLE "authors"
  ADD FOREIGN KEY ("author_id") REFERENCES "users" ("user_id")
  DEFERRABLE INITIALLY IMMEDIATE;

ALTER TABLE "blog_posts"
  ADD FOREIGN KEY ("author_id") REFERENCES "authors" ("author_id")
  DEFERRABLE INITIALLY IMMEDIATE;

ALTER TABLE "post_categories"
  ADD FOREIGN KEY ("blog_post_id") REFERENCES "blog_posts" ("blog_post_id")
  DEFERRABLE INITIALLY IMMEDIATE;

ALTER TABLE "post_categories"
  ADD FOREIGN KEY ("cat_id") REFERENCES "categories" ("cat_id")
  DEFERRABLE INITIALLY IMMEDIATE;

ALTER TABLE "comments"
  ADD FOREIGN KEY ("blog_post_id") REFERENCES "blog_posts" ("blog_post_id")
  DEFERRABLE INITIALLY IMMEDIATE;

ALTER TABLE "comments"
  ADD FOREIGN KEY ("user_id") REFERENCES "users" ("user_id")
  DEFERRABLE INITIALLY IMMEDIATE;

ALTER TABLE "post_view_count"
  ADD FOREIGN KEY ("blog_post_id") REFERENCES "blog_posts" ("blog_post_id")
  DEFERRABLE INITIALLY IMMEDIATE;

ALTER TABLE "post_view_logs"
  ADD FOREIGN KEY ("blog_post_id") REFERENCES "blog_posts" ("blog_post_id")
  DEFERRABLE INITIALLY IMMEDIATE;
```

## 6. Data Integrity & Constraints

### 6.1 Deferrable Constraints
All foreign keys are defined as `DEFERRABLE INITIALLY IMMEDIATE`. This means:
- By default, constraints are checked **immediately** after each statement.
- Within a transaction, you can run `SET CONSTRAINTS ALL DEFERRED` to delay validation until `COMMIT`, enabling complex multi-table inserts.

### 6.2 Unique Constraints
- `users.username` — prevents duplicate display names.
- `users.email` — enforces one account per email address.
- `categories.category_name` — category labels must be unique.
- `post_categories(blog_post_id, cat_id)` — composite PK prevents duplicate categorization.

### 6.3 NOT NULL Constraints
- Core identity fields (`username`, `email`, `password`, `title`, `content`, `comment.content`) are mandatory.
- All foreign key columns in child tables are `NOT NULL` to enforce referential integrity.

## 7. Performance Considerations

| Strategy | Implementation | Benefit |
|----------|----------------|---------|
| **Denormalized view counter** | `post_view_count` table | Avoids expensive `COUNT(*)` on large `post_view_logs`. |
| **Targeted indexes** | On `author_id`, `post_status`, `blog_post_id`, `user_id` | Speeds up common query patterns (list by author, filter by status, analytics). |
| **Junction table PK** | Composite PK on `post_categories` | Enforces uniqueness and provides a clustered index for joins. |

### Recommended Future Optimizations
- Add a **partial index** on `blog_posts(post_status)` where `post_status = 'published'` for faster public feed queries.
- Consider **partitioning** `post_view_logs` by `viewed_at` (e.g., monthly) if view volume is high.

## 8. Known Limitations & Future Improvements

| # | Limitation | Suggested Improvement |
|---|------------|----------------------|
| 1 | **No soft delete** | Add `deleted_at` TIMESTAMP to `blog_posts`, `comments`, and `users` for recoverable deletions. |
| 2 | **Flat comments** | Add `parent_comment_id` self-referencing FK to `comments` for threaded discussions. |
| 3 | **No tags** | Add a `tags` table and `post_tags` junction for flexible labeling beyond categories. |
| 4 | **No media management** | Add an `attachments` or `media` table linked to `blog_posts` for images and files. |
| 5 | **No post versioning** | Add a `post_revisions` table to track edit history. |
| 6 | **No SEO metadata** | Add `slug`, `meta_title`, `meta_description` columns to `blog_posts`. |
| 7 | **No full-text search** | Add a `tsvector` column or use PostgreSQL's built-in full-text search on `blog_posts.content`. |
| 8 | **No rate limiting on views** | A single user can inflate view counts; consider deduplication logic (e.g., 1 view per user per hour). |

## 9. Sample Query Patterns

### List all published posts with author and category info
```sql
SELECT
  bp.blog_post_id,
  bp.title,
  bp.published_at,
  a.first_name || ' ' || COALESCE(a.last_name, '') AS author_name,
  c.category_name,
  pvc.view_count
FROM blog_posts bp
JOIN authors a ON bp.author_id = a.author_id
LEFT JOIN post_categories pc ON bp.blog_post_id = pc.blog_post_id
LEFT JOIN categories c ON pc.cat_id = c.cat_id
LEFT JOIN post_view_count pvc ON bp.blog_post_id = pvc.blog_post_id
WHERE bp.post_status = 'published'
ORDER BY bp.published_at DESC;
```

### Get comment count per post
```sql
SELECT
  blog_post_id,
  COUNT(*) AS comment_count
FROM comments
GROUP BY blog_post_id;
```

### Increment view count (application logic)
```sql
-- Step 1: Log the view
INSERT INTO post_view_logs (blog_post_id, user_id)
VALUES (:post_id, :user_id);

-- Step 2: Update the counter
INSERT INTO post_view_count (blog_post_id, view_count)
VALUES (:post_id, 1)
ON CONFLICT (blog_post_id)
DO UPDATE SET view_count = post_view_count.view_count + 1;
```
